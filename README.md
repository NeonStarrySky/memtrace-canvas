# memtrace-canvas

实时查看本机程序的内存读取轨迹。采集器用 DynamoRIO 读取访问地址、线程和发起读取的指令地址（PC），网页用点图展示它们。也可以用模拟演示比较不同的数据布局。[项目结构](PROJECT_STRUCTURE.md)

## 快速体验

安装 Node.js 18 或更新版本，在仓库根目录运行以下命令。打开终端显示的本地地址，默认端口为 `8787`。页面会自动播放演示数据。

```sh
node server/server.mjs --demo
```

想先看看真实采集的效果，可以播放命令行 C++ 粒子系统的 52 秒实录。[粒子系统动图](examples/particle-trace.gif)

## 启动并监测本机程序

1. 安装与目标程序架构匹配的 DynamoRIO，把 `drrun` 加入 `PATH`。也可以设置 `RAM_TRACE_DRRUN` 为其完整路径。Linux x86-64 已验证，Windows 上的实际引擎启动仍待实机验证。[DynamoRIO 下载](https://github.com/DynamoRIO/dynamorio/releases)
2. 在仓库根目录运行 `node server/server.mjs`，打开终端显示的地址。
3. 在「启动程序」面板浏览或填写可执行文件和工作目录。工作目录留空时使用可执行文件所在的目录。有程序参数时每行填一个，含空格的路径也放在同一行。
4. 点「启动并监测」。运行时可以调整筛选条件。点「停止程序」会结束该程序及其采集。

用 PowerShell 指定 DynamoRIO 路径的示例：

```powershell
$env:RAM_TRACE_DRRUN = 'C:\DynamoRIO\bin64\drrun.exe'
node server/server.mjs
```

对 NeonEngine，选择其 `x64\Release\Engine.exe`，将工作目录设为 NeonEngine 的 `Engine` 子目录，方便引擎找到 `assets\shaders`。[NeonEngine 启动说明](https://github.com/NeonStarrySky/NeonEngine#run-the-demo)

## 组合筛选

同类选项满足任意一项即可，不同栏位同时生效。可在启动前填写，也可以在采集过程中点「应用筛选」。

| 条件 | 填法 |
| --- | --- |
| 发起读取的模块 | 点「仅主程序」，或填写 `Engine.exe, glfw3.dll`。采集发现模块后也可以勾选多个。模块归属根据指令地址判断。 |
| 线程 | 填一个或多个线程 ID，例如 `7028, 9012`。 |
| 起始、结束读地址 | 用 `0x` 开头的虚拟地址，包含端点。这里筛的是被读取的数据地址。 |
| 最小、最大跳距 | 填字节数，例如 `4` 到 `1024`。图上会标出最新匹配跳转的起点和终点。 |

跳距默认使用同一线程中**实际相邻的两次读取**，两次读取都须满足模块和读地址条件。若想观察过滤后的序列，可以选择「筛选后的同线程读取」。重新应用筛选会重算最近 16,384 条读取，并继续统计之后的新读取。

「适配全部」显示当前匹配范围。「适配近期」聚焦最近收到的 32 个匹配点。整个进程的虚拟地址跨度很大时，可以用模块、线程或地址范围缩小观察范围。

## 缩放和拖动

- 在点图内滚动鼠标滚轮，围绕光标缩放。放大后按住鼠标左键，可以上下左右拖动。触屏支持双指缩放和单指拖动。
- 工具栏的 `+` 和 `−` 围绕画面中心缩放，支持 100%–3200%。「适配全部」和「适配近期」都会恢复到 100% 并重新跟随读取。
- 手动查看时，「基准范围」是开始操作时用来生成点图的地址范围。采集和统计继续进行。用「适配全部」可以查看之后扩张的范围。应用筛选或启动新程序时会恢复全范围跟随。

## 运行排查

- **没有匹配点**时，先看「已采集读取」是否增长，并核对已检测到的模块名、线程和地址条件。
- **程序没有弹窗**时，用相同的工作目录直接运行可执行文件，检查终端里的窗口、显卡或着色器初始化日志。模块筛选在采集后执行，在线采集仍会记录整个目标进程的轨迹。
- **只想看模拟内存**时，可以用浏览器打开仓库根目录的 [index.html](index.html)。
